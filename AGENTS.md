# Project guidance

- The architecture source of truth is `docs/kafka-successor-architecture.md`; the product problem catalogue is `docs/kafka-pain-points.md`; product motivation and Kafka equivalents are in `docs/why-whitewater.md`; operational experience requirements are in `docs/operational-experience.md`.
- `docs/tasks.md` is the living execution tracker. Keep one current-focus milestone, mark work in progress before implementation, and check items only after linked tests/evidence pass.
- Preserve the public model `fabric -> space -> feed -> key -> cursor -> subscription`; do not expose physical partitions.
- WCL commands, HTTP control requests, CLI commands, SDKs, and future MCP tools must converge on the typed `ControlController`; do not duplicate resource semantics in interface layers.
- Whitewater Streams must offer the same Writer, Reader, Subscription, StateStore, Pipe, Cursor, retry, and atomic-effect semantics in Rust, Python, Java, C#, Node.js/TypeScript, and Go. Java is not the privileged processing runtime; gate published features and runnable guides on one cross-language three-Node conformance suite, with explicit unsupported capabilities. Node.js record nanoseconds use bigint/decimal strings, never imprecise JavaScript numbers.
- Standard three-Node development uses the OpenRaft-backed Control Plane and reports `control_plane` authority only after majority commit. `local_prototype` is reserved for Nodes without Control Plane configuration.
- Public terminology is Control Plane; Raft, voters, and majority quorum are internal correctness mechanisms rather than user-managed resources.
- Feed names use lowercase dotted segments matching `^[a-z][a-z0-9]*(\.[a-z][a-z0-9]*)*$` with a 512-byte maximum, while immutable FeedId values carry identity across renames.
- Supported Fabrics require at least three Nodes and three active replicas, including the standard development topology.
- Treat Whitewater as both a distributed database and a streaming platform: Feeds provide immutable temporal history, while persisted replicated Indexes provide current and queryable state.
- Record-attached arbitrary key/value bytes are called Metadata, never Headers; reserve header terminology for transport protocols such as HTTP.
- Every record stores signed 64-bit Unix epoch nanoseconds in `event_time_ns` and `ingest_time_ns`; do not reduce record time to milliseconds. JSON represents these as decimal strings to avoid JavaScript precision loss.
- Standalone Readers own independent current Cursors; every named Subscription owns independent durable acknowledged progress shared only by Readers cooperating in that Subscription.
- Use `C:\Code\Stackapps\kafka-trunk` as a read-only implementation reference and record retained lessons in `docs/kafka-source-lessons.md`; preserve proven correctness behavior without copying Kafka's public partition coupling.
- Feed history has one immutable semantic model; use explicit persisted replicated Indexes rather than cleanup-policy or compacted-Feed modes. A Space is an administrative namespace, not a Feed cleanup-policy variant.
- Application-defined secondary Indexes are part of Whitewater's core storage contract. Use stable Feed/application-Key or MessageId references, a small shared set of bounded keyspaces rather than one LSM tree per Index, serializable primary/posting/uniqueness updates, and applied-Cursor fencing. Never claim a Fjall-local transaction atomically commits the separate Active Range log; do not expose Index queries until replicated correctness is proven.
- StateStores belong to Spaces: Feed-derived stores name their source FeedId, while manual stores require their own replicated mutation journal and checkpoint. A Space is not a log. Enrichment must support Reader → logical StateStore lookup by application Key → Writer without client co-partitioning; commit input progress and output effect idempotently or fail closed. A `declared` StateStore is metadata only, never a live data service.
- Managed Pipes should provide rolling-window aggregation as a built-in StateStore view with identical semantics in all six SDKs: users declare business Key, duration, and aggregation, not sliding step, panes, partitions, local Fjall, or a required fourth Node. Event time, watermark/lateness, retention, revision, cost bounds, RF3 state, and epoch-fenced movable compute leases must be explicit and tested before claiming window support.
- The pinned Fjall dependency currently backs only an isolated local Index prototype; it has not been selected as the replicated Index Engine. Benchmark and fault-test Fjall against alternatives before a production storage decision, and retain an engine abstraction until then. Keep blocking Fjall operations off Tokio workers when integrating the prototype.
- Client traffic uses TLS. Inter-Node traffic requires authenticated encryption and verified Node identity: native mTLS is the default, while a trusted service mesh or equivalent orchestrator transport is an allowed mechanism when identity, rotation, audit, and downgrade prevention are verified. API keys authorize access but must never be used directly as encryption keys.
- Prioritize correctness contracts before throughput optimization.
- The host may not have Rust installed. Verification can run with `rust:1.90-bookworm` in Docker.
- Final verification is mandatory **after the last edit**, before marking work complete or committing: run `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings`, and `cargo test --all-targets` (which includes Rust unit and integration tests). Targeted tests during development do not replace the full final run; rerun affected and full checks after a subsequent code edit.
- Also run every repository-maintained Python/Docker integration, fault, and live acceptance script (`scripts/test-*.py`) as the final end-to-end gate for code changes, sequentially in an isolated disposable test Fabric; check each script's Compose/project/volume effects first. Several scripts stop/restart Nodes or `--force-recreate` the default Compose Fabric. Never disrupt an existing Fabric, alter its persistent volumes, or perform destructive cleanup without specific user confirmation. If safe isolation, Docker, credentials, or a required service is unavailable, report each skipped/failed suite and the blocker; never claim "all tests passed" or mark live acceptance done.
- Standard development and membership testing use `compose.cluster.yml` with at least three Nodes via `docker compose up --scale node=N`.
- The current gossip-style membership is discovery only, not consensus or record replication.
- Autoscaling must use sustained thresholds, hysteresis, cooldowns, and one-node steps.
- Never scale in a node unless ownership/data draining has completed and the node reports safe-to-remove. Do not use the legacy metadata-only owner transfer as an operator shortcut; owner moves require a verified frozen committed boundary and a compare-and-set Control Plane cutover.
- Infrastructure scaling runs outside data nodes; do not mount Docker or orchestrator credentials into a data node.
